# B2-1 발표용 설명: 나만의 용돈 기입장

## 1. 프로젝트 소개

Python 3.10 이상과 표준 라이브러리만으로 만든 콘솔 가계부입니다. 거래 추가·조회·검색·수정·삭제, 월별 요약, 예산 관리, 카테고리 관리, CSV 가져오기·내보내기를 지원합니다. 프로그램을 종료해도 `data/`의 JSONL 파일 3개에 기록이 남습니다.

**발표 한 문장:** “사용자 명령을 처리하는 CLI와 거래 규칙, 파일 저장을 분리하고, 큰 파일도 줄 단위로 처리하도록 만든 용돈 기입장입니다.”

## 2. 실행 시연 순서

`B2-1` 폴더에서 다음 순서로 시연합니다. `add` 입력에서는 날짜 `2024-01-15`, 타입 `expense`, 카테고리 `food`, 금액 `15000`, 메모 `점심`, 태그 `meal`을 입력합니다. 출력된 ID를 마지막 수정·삭제 명령에 사용합니다.

```bash
python3 -m budget_app category list
python3 -m budget_app add
python3 -m budget_app list --limit 5
python3 -m budget_app search --category food --tag meal
python3 -m budget_app budget set --month 2024-01 --amount 10000
python3 -m budget_app summary --month 2024-01 --top 3
python3 -m budget_app export --out demo.csv --month 2024-01
python3 -m budget_app update --id <출력된-ID> --amount 9000
python3 -m budget_app delete --id <출력된-ID>
```

위 예산 10,000원에 지출 15,000원을 넣으면 요약에서 **사용률 150.0%**와 초과 경고가 나옵니다. `import` 시연에는 README의 CSV 예제를 `sample.csv`로 저장한 뒤 `python3 -m budget_app import --from sample.csv`를 실행하면 됩니다.

## 4. 제너레이터와 스트리밍을 설명하는 방법

`LedgerStore.transactions()`는 파일을 열고 한 줄을 JSON으로 변환할 때마다 `yield Transaction.from_dict(...)`를 실행합니다. 따라서 파일 전체를 `read()`나 `list()`로 메모리에 올리지 않습니다. `summary`도 이 반복자를 한 번 순회하며 합계만 유지합니다.

`list`와 `search`는 날짜 최신순이 필요합니다. 단순히 모든 거래를 메모리에 넣고 정렬하면 대용량 파일에서 메모리가 커집니다. 그래서 `newest_first()`는 최대 1,000건씩만 정렬해 임시 파일로 쓰고, `heapq.merge()`로 정렬된 묶음을 합쳐 한 건씩 `yield`합니다. **메모리 사용은 전체 거래 수가 아닌 묶음 크기와 묶음 개수에 좌우됩니다.**

**발표 문장:** “`yield`는 다음 거래가 필요할 때만 한 줄을 읽습니다. 최신순 정렬도 작은 묶음으로 나눠 처리해 파일이 커져도 전체 거래를 RAM에 담지 않습니다.”

## 5. 데이터 안전성을 설명하는 방법

수정·삭제는 기존 파일을 바로 덮어쓰지 않습니다. 같은 폴더에 임시 파일을 만들고 새 내용을 끝까지 기록한 뒤 `os.replace()`로 교체합니다. 입력 검증이나 쓰기 중 오류가 나면 임시 파일만 제거하고 원래 파일을 유지합니다. CSV 가져오기도 먼저 각 행의 날짜, 타입, 카테고리, 양수 금액을 확인해 임시 파일에 준비한 다음 반영합니다. 카테고리·예산 파일 갱신에도 같은 교체 방식을 사용합니다.

**발표 문장:** “잘못된 수정값이나 CSV 한 행의 오류 때문에 기존 거래 파일이 반쯤 바뀌지 않도록, 완성된 파일만 교체합니다.”

## 6. 데코레이터와 타입 힌트를 설명하는 방법

`@timed`는 `main()` 앞뒤의 시간 측정을 감싸는 데코레이터입니다. CLI 명령 코드마다 측정 코드를 복사하지 않아도 되고, `BUDGET_APP_TIMING=1`로 필요할 때만 결과를 확인할 수 있습니다. 타입 힌트 예시로 `BudgetService.summary(self, month: str, top: int) -> Summary`는 입력이 월 문자열과 개수이며 출력이 `Summary` 객체임을 보여 줍니다. `LedgerStore.transactions() -> Iterator[Transaction]`은 결과를 한 건씩 생성한다는 계약을 드러냅니다. 타입 힌트 자체가 런타임 검증을 대신하지는 않으므로 실제 값 검증 함수도 별도로 구현했습니다.

## 7. 질문 대비

**왜 JSONL을 선택했나요?** 한 줄에 거래 하나를 저장하므로 거래를 순차적으로 읽고 새 거래를 끝에 붙이기 쉽습니다. CSV는 사용자와 데이터를 주고받는 형식으로만 사용했습니다.

**왜 ID가 필요한가요?** 날짜·금액이 같은 거래도 구별하고, 수정·삭제 대상을 정확히 지정하기 위해서입니다. UUID 기반 ID를 새 거래마다 부여합니다.

**없는 ID나 잘못된 입력은 어떻게 처리하나요?** 사용자에게 원인과 확인 방법을 보여 주고 오류 종료 코드 1을 반환합니다. 테스트에서 스택트레이스가 출력되지 않는 것도 확인합니다.

**카테고리를 지우면 기존 거래는 어떻게 되나요?** 사용 중인 카테고리는 삭제를 막습니다. 해당 거래의 카테고리를 먼저 변경하거나 거래를 삭제해야 합니다.

**같은 CSV를 두 번 가져오면 어떻게 되나요?** 매번 새 ID를 부여하므로 거래가 두 번 추가됩니다. 중복 제거는 이번 과제 범위 밖이며, 사용자에게 README에 이 동작을 명시했습니다.
