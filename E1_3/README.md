# E1_3 — Mini NPU Simulator (MAC 연산 시뮬레이터)

AI 모델의 핵심 연산인 MAC(Multiply-Accumulate)을 순수 반복문으로 구현해, 3×3 사용자 입력과 `data.json`의 5×5/13×13/25×25 데이터를 대상으로 Cross(십자가)/X 패턴을 판별하고 크기별 연산 시간을 측정하는 콘솔 프로그램입니다.

## 실행 방법

```bash
python3 main.py
```

- 실행하면 `[모드 선택]`에서 `1`(사용자 입력, 3×3) 또는 `2`(`data.json` 분석)를 입력합니다.
- `data.json`은 `main.py`와 같은 폴더에 있어야 합니다(코드가 스크립트 위치 기준으로 자동 탐색).
- 모드 1은 필터 A, 필터 B, 패턴을 각각 3줄씩 공백으로 구분해 입력받습니다. 숫자 개수가 맞지 않거나 파싱에 실패하면 안내 문구를 출력하고 해당 줄을 다시 입력받습니다.

## 구현 요약

- **라벨 정규화**: `{'+': 'Cross', 'cross': 'Cross', 'x': 'X'}` 딕셔너리 하나로 `expected` 값(`'+'`/`'x'`)과 필터 키(`'cross'`/`'x'`)를 모두 표준 라벨(`Cross`/`X`)로 변환합니다(`normalize_label`). 콘솔 출력과 PASS/FAIL 비교는 항상 이 표준 라벨을 기준으로 합니다.
- **MAC 연산**: `mac_score(pattern, filter_)`가 이중 for문으로 같은 위치의 값을 곱해서 누적합을 구합니다. NumPy 등 외부 라이브러리는 사용하지 않았습니다.
- **동점 처리 정책**: `judge_label`이 `abs(score_cross - score_x) < 1e-9`이면 `UNDECIDED`를 반환합니다. 채점 규칙상 `UNDECIDED`는 expected와 무관하게 항상 FAIL로 처리됩니다.
- **성능 측정**: `measure_avg_ms`가 MAC 연산을 10회 개별 호출해 각각 `time.perf_counter()`로 측정한 뒤 평균(ms)을 냅니다. 모드 2에서는 `data.json`에 없는 3×3 크기를 벤치마크하기 위해 내부적으로 십자가 패턴을 생성하는 `generate_cross(n)`을 사용합니다.
- **스키마 검증**: `data.json`의 패턴 키(`size_{N}_{idx}`)에서 정규식으로 `N`을 뽑아 해당 크기의 필터가 로드됐는지, 패턴 크기가 필터 크기와 일치하는지 확인합니다. 문제가 있으면 그 케이스만 FAIL로 남기고 프로그램은 계속 진행합니다(예외를 케이스 단위로 잡아서 처리).

## 결과 리포트

### 실제 실행 결과 (`data.json`, 2026-08-05 기준)

```
총 테스트: 6개
통과: 3개
실패: 3개

실패 케이스:
- size_13_2: 동점(UNDECIDED) 처리 규칙에 따라 FAIL
- size_25_1: 동점(UNDECIDED) 처리 규칙에 따라 FAIL
- size_5_1: 동점(UNDECIDED) 처리 규칙에 따라 FAIL
```

### FAIL 원인 분석 — 3건 모두 "수치 비교 문제"

3건의 FAIL은 라벨/스키마 문제가 아니라 **부동소수점 오차**로 인한 것입니다. `data.json`의 `size_5_1`, `size_13_2`, `size_25_1` 필터는 값을 의도적으로 조금씩 어긋나게 설계해(예: 십자가 필터 중앙값을 1.0이 아닌 0.9로, X 필터 대각선을 1.0이 아닌 0.1×여러 칸으로) 수학적으로는 Cross 점수와 X 점수가 정확히 같아지도록(동점) 만들어 놓았습니다. 그런데 컴퓨터가 실수를 더하는 순서와 방식이 Cross 쪽(한 번에 0.9를 더함)과 X 쪽(0.1을 여러 번 나눠서 더함)에서 다르기 때문에, 이진 부동소수점 표현의 반올림 오차가 누적돼 `0.9`와 `0.8999999999999999`처럼 이론상 같아야 할 값이 미세하게 달라집니다. 이 세 케이스는 `abs(score_cross - score_x) < 1e-9` 규칙에 걸려 `UNDECIDED`로 판정되고, 채점 규칙상 `UNDECIDED`는 `expected`가 무엇이든 무조건 FAIL로 집계됩니다. 즉, 로직 오류가 아니라 "동점을 FAIL로 간주한다"는 정책과 부동소수점의 본질적 한계가 만나 생긴, 데이터셋이 의도한 결과입니다. 만약 epsilon 비교 없이 `==`로 직접 비교했다면 두 값이 미세하게 달라서 오히려 (우연히) 한쪽으로 판정이 갈렸을 것이고, 그 판정이 `expected`와 맞는지는 순전히 반올림 방향에 달린 운의 문제가 됩니다 — epsilon 정책은 바로 이런 "우연한 정답/오답"을 막고 "판정 불가"임을 명시적으로 드러내기 위해 필요합니다.

나머지 3건(`size_5_2`, `size_13_1`, `size_25_2`)은 필터 간 점수 차이가 충분히 커서 epsilon 문제 없이 명확하게 판정되었고, 모두 `expected`와 일치해 PASS했습니다.

### 성능 표 및 시간 복잡도(O(N²)) 분석

```
크기       평균 시간(ms)    연산 횟수
-------------------------------------
3×3            0.002           9
5×5            0.004           25
13×13          0.018           169
25×25          0.089           625
```

`mac_score`는 N×N 패턴과 필터의 모든 칸을 정확히 한 번씩 곱하고 더하므로 연산 횟수는 항상 N²입니다(3×3=9, 5×5=25, 13×13=169, 25×25=625 — 표의 "연산 횟수" 열과 정확히 일치). 표의 평균 시간도 이 연산 횟수 증가와 같은 추세로 늘어납니다: 3×3→5×5는 연산 횟수가 약 2.8배(9→25) 늘 때 시간도 약 2배 늘었고, 5×5→13×13은 연산 횟수가 약 6.8배(25→169) 늘 때 시간은 약 4.5배, 13×13→25×25는 연산 횟수가 약 3.7배(169→625) 늘 때 시간은 약 4.9배 늘었습니다. 측정값이 짧은 시간 단위(ms)라 시스템 잡음(캐시, OS 스케줄링 등)의 영향을 받아 배율이 딱 떨어지지는 않지만, 전체적으로 "패턴 한 변의 길이가 k배가 되면 소요 시간은 대략 k²배가 된다"는 O(N²) 경향이 뚜렷하게 나타납니다. 이는 `mac_score`의 이중 for문 구조(바깥 루프 N번 × 안쪽 루프 N번)가 곧 O(N²)이라는 것과 정확히 대응됩니다. 실제 AI 모델의 필터가 이보다 훨씬 크고 개수도 훨씬 많아지면, 이 N²의 증가폭이 CPU의 직렬 처리로는 감당하기 어려운 수준이 되기 때문에 병렬 MAC 연산에 특화된 NPU가 필요해지는 이유이기도 합니다.
